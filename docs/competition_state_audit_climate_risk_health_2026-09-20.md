### 🔴 L1 — Anchor OOF artifact no longer matches its own state metrics (score-provenance break)

| **Current** anchor OOF file vs macro/refit/dlnm feature CSVs (variant order) | 0.7908 | **0.7335** | 0.7679 |

- `pearson(current_anchor_file, correct_oof) = 0.80`; value sets differ → the 10:34 UTC regeneration wrote a **different model/fold assignment**, not a pure reorder.
- SKILL_STATE still reports `anchor_oof_auc = 0.813342` / `anchor_oof_score = 0.815654` (the Sep-1 metrics), but the artifact referenced by `scores_file` no longer reproduces them under **any** label file on disk.
- Every downstream consumer of `scores/branch_anchor-baseline_oof.json` (refit scripts, skill_07 residual trainer, skill_08 `_run_residual_specialist`) reads a vector misaligned with the labels it is compared/trained against.
### 🔴 L2 — Residual targets are row-mispairings (length-only alignment)

- Label order of `features_train_anchor-baseline.csv` ≠ orders of `features_train_macro-stress-geofence*.csv` / `features_train_residual-dlnm-specialist.csv` / `features_train_catboost-specialist.csv` (**5.34% mismatch**; all variant CSVs share one common order, the anchor CSV uses another).
- `scripts/refit_macro_stress_geofence.py` (L58–62), `scripts/refit_residual_dlnm_specialist.py` (L85–86), and `skill_08._run_residual_specialist` (L1156–1157) all pair `y_true` (variant CSV order) with `anchor_oof` (scores file) asserting **`len` only** — no ID/order check.
- Result: the "residual specialist" targets are corrupted; the documented OOFs (0.7872 refit / 0.8089–0.8172 dlnm) and the sub_018 LB story are artifacts of this mispairing.

### 🔴 L3 — CV-split provenance lie → test-time spatial exploitation ("the leakage")

- `cv_split_indices.json` / `cv_split_groups.json` live in **`scores/`**; the untracked scripts and the plugin check **`data/processed/cv_split_indices.json` — which does not exist** → silent fallback to **random `KFold(seed=42)`** (plugin also hardcodes `random_seed=42`).
- The anchored training uses **BufferedSpatialCV** (5 km Haversine buffer, 15 location groups). Under random folds the residual model can split on `latitude`/`longitude`/`location` and exploit **same-area training rows the anchor was forced to be blind to** — so its test predictions genuinely benefit from spatial proximity that its own OOF (and the label) forbid. That is exactly the **OOF 0.7872 → LB 0.8303 (+0.043)** inversion.
- Meanwhile OOF records were tagged **`cv_strategy_id: "config:BufferedSpatialCV"`** (hardcoded in `refit_macro_stress_geofence.py` L183; via `resolve_active_cv_strategy_id` elsewhere) — **false provenance on persisted records** (SoT OOF-contract violation).
- Note: the in-skill trainers (`skill_07`/`skill_08`) DO use `load_explicit_cv_splits(state)` → official spatial splits (state has `cv_split_indices`); only the untracked scripts fell back. The residual-dlnm re-run on Sep 3 was therefore internally consistent *except* for L1/L2 misalignment.

Both untracked refit scripts fit `LabelEncoder` on `pd.concat([train[col], test[col]])` — test vocabulary/statistics leak into the transform (violates the zero-leakage contract).

## 12. Round 3 — merge_asof Blast-Radius Audit (root cause closed)

> Status: **CONFIRMED CORRUPTION, not methodology.** Follow-up audit after the consolidated report above. The corruption is no longer a hypothesis about OOF misalignment — it is a reproduced, deterministic row-scramble in the shared external-join pattern, affecting 14 of 21 training feature files.

### 12.1 Root cause (reproduced 1:1)

Both plugins execute the same dangerous sequence: `sort_values(by=deathdate) → merge_asof(on=deathdate, by=[lat, lon], direction=backward) → .loc[<original>.index]` positional restore.

- `plugins/macro_stress_extractor.py` L69–95 — **config-default plugin** (`challenge_config.json` L44 `feature_extraction_plugin: plugins.macro_stress_extractor`), committed in `7955952`.
- `plugins/advanced_spatial_temporal_extractor.py` L258–280 — untracked.

Mechanism (verified): `Train.csv` contains **111 rows inside duplicate `(deathdate, latitude, longitude)` groups** (56 duplicate keys; up to 3 rows per key). `merge_asof` output therefore carries a non-unique index, and `.loc[RangeIndex]` matches *multiple rows per label*, silently dropping/duplicating rows and producing a same-length but partially scrambled frame. Reproduction against real data with the exact plugin code yields **coord_shift=368, label_shift=168** — identical to every corrupted artifact on disk. The ID-carrying restore (`set_index('ID').reindex(raw['ID'])`) yields **0/0**.

The parquet inputs themselves are clean (`aligned_macro_proxies.parquet` and `macro_stress_proxies.parquet`: 305,360 rows, **0 duplicate `(deathdate, lat, lon)` keys**): the collision is on the **left (train/test) side** — multiple deaths at the same location on the same date.

Combined with skill_07/`skill_14`'s positional fallback zipping raw `Train.csv` IDs onto model outputs, "the file's ID column is honest; what it's attached to isn't" applies repo-wide.

### 12.4 Impact statement

Every OOF number and submission produced through either affected plugin — DLNM lags, spatial smoothing, macro-stress geofencing, all catboost/xgb specialist variants, and the full ensemble branch — was trained and evaluated on data where age, coordinates, and label were shuffled against each other in 368 rows (train). None of those numbers can be trusted until regenerated. The 0.9-goal engineering effort since Sep 2 was validated against scrambled inputs; the *ideas* remain literature-backed but **untested**.

### 12.5 Fix validated — shared utility (design confirmed by reproduction)

The fix that makes this class of bug structurally impossible:

1. **One shared join utility** (all plugins call it; no hand-rolled sort-merge-restore anywhere):
   `sorted_asof_join(df, ext_df, id_col, date_col, by_cols, direction="backward")` — carries `id_col` through the sort and merge, restores original order with `set_index(id_col).reindex(df[id_col])`, and **asserts the returned frame's ID column equals the input's ID column in original order before returning**.
2. **Unit test with duplicate dates** — synthetic frames with duplicate `(date, by)` keys asserting row-for-row ID preservation; reproduces this exact bug if the utility regresses.
3. **Regenerate** all 14 macro-featured branches' features/OOF from scratch through the validated join, then re-run gates (notably residual-dlnm), then re-lock selections (sub_008 slot is currently invalid).
